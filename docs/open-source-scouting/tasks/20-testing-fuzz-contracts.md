# Testing, fuzzing y contratos

Investigar proyectos publicos de property-based testing, stateful testing,
contract tests, VCR/mock servers, fault injection, time travel y UI testing.

Aplicar una tecnica nueva a un riesgo real de RRSS que las pruebas actuales no
cubran. Debe producir un fallo reproducible o una barrera de regresion util, ser
offline y funcionar en Windows/Linux. No crear tests tautologicos ni snapshots
que solo congelen la implementacion.
